1. 활용 AI 모델·도구

[서비스] Google Gemini API(gemini-4-hydrogen): 질문 의도 파악과 계획 수립, 함수 호출로 도구 11개 중 필요한 것을 선택(원문 확인·공고 검색·자격 대조·서류 검수·대안 찾기·되묻기 등), 첨부 서류 판독, 답변과 사유서·소명서 초안 작성. 질문 난이도를 먼저 판단해 추론 수준(기본 medium, 복잡한 해석은 high)을 자동 전환. Gemini 내장 Google 검색: 최신 공고·일정 확인과 출처 표시.

[개발] Claude(Anthropic, Opus 5.5): 대회 규칙·심사 기준 분석, 자료조사(통계·공식 안내 찾기), 배포 서비스 점검(QA)과 개선점 도출, 공공데이터 API 선정 검토, 제출 문서 초안 작성 보조. Claude Code 2.1.220(Claude Opus 5.5·Fable 5.2): 서비스 코드 대부분 작성. Antigravity 2.32.1(Gemini 4 Argon·Gemini 4 Hydrogen): MVP 첫 버전과 가벼운 버그 수정. Stitch 2.0(Google): 화면 디자인. Nano Banana·Neon(Google): 로고 생성과 SVG 변환. ChatGPT(OpenAI): 자료조사(문제 정의 근거·비교 서비스·공식 안내 링크 찾기). 찾은 사실은 출처 페이지에서 다시 확인함.

2. AI 활용 범위와 팀의 기여

기획: 대상 사용자(정부·지자체 지원 정책 신청을 준비하는 청년), 문제 정의(공고문에 흩어진 탈락 조건, 서류 반려, 제출 후에야 알게 되는 결과), 서비스 흐름은 팀이 설계함. 보조금24·복지로·온통청년을 따로 찾아 자격과 서류를 대조하던 일을 한 번의 대화로 사전 점검하고, 반려 전에 서류 문제를 알려 주는 것을 목표로 함.

설계·개발: 에이전트 구조(도구 11개의 역할과 입력 형식, 최대 9회 도구 실행 루프), AI 행동 규칙 프롬프트(금액은 공식 원문 확인 후 답변, 정보가 없으면 추측하지 않고 되묻기, 안 되면 대안 찾기), 공공 API 4종 연동, 배포 환경은 팀이 설계함. 코드는 전부 AI(주로 Claude Code)가 작성했고, 팀은 요구사항을 정해 지시하고 결과를 실행·검토해 통합함.

서비스 동작: Gemini가 계획 수립, 도구 선택, 서류 판독, 문장 작성을 맡음. 자격 조건 대조, 소득 비율 계산, 답변 검증, 대안 공고 정보 확정은 LLM 판단이 아닌 서버 규칙 코드가 수행함. 이 코드의 조건·계산식·검사 기준은 팀이 공고 원문을 근거로 정함.

검증·문서: AI가 가상 신청자 테스트 데이터와 문서 초안을 만들고, 팀이 공고 원문과 대조해 정답과 수치를 확정하고 최종 내용을 검토함.

3. API·외부 데이터·오픈소스

API: 행정안전부 대한민국 공공서비스(혜택) 정보 API(보조금24, 공고·구비서류·금액 대조), 한국사회보장정보원 지자체·중앙부처복지서비스 API(복지로, 지역·전국 복지 공고와 원문), 한국고용정보원 청년정책 API(온통청년, 조건·금액 대조), ScrapeCreators 인스타그램 API(Treg 경유, 캡션과 음성 인식 대본 텍스트만 조회), Google Gemini API와 내장 Google 검색.

외부 데이터: 2026년 기준 중위소득(보건복지부 고시, 소득 비율 계산). 직접 생성한 데이터: 가상 서류 세트 3종, 서류 9건(시연·서류 검수 테스트), 가상 신청자 15명(판정 정확도 테스트). 실제 개인정보는 쓰지 않음.

오픈소스·플랫폼: Next.js 14, React 18, TypeScript, Tailwind CSS, Vercel(배포) 등. AI SDK·에이전트 프레임워크 없이 Gemini API를 직접 호출하고 엑셀·워드 파일도 직접 생성함. 템플릿: 해당 없음. 상세 출처는 소개서 별첨에 기재함.

4. 검증 및 한계 대응

확인 방법: 배포 환경에서 추천·자격 확인·서류 검수·산출물 흐름을 실행해 테스트함(공공 API 4종 실제 호출, 시연 서류 3건의 주소·성명·전입일 문제 탐지, 생성 파일 Office 열람). 최종 답변은 서버가 최대 9가지 규칙(형식, 계산 수치, 판정 일치, 지난 마감일, 확정 표현, 대안 제시, 원문 금액, 파일 생성, 링크)으로 다시 검사하고, 고칠 점이 있으면 한 번 다시 쓰게 함. 답변 링크와 출처 목록에는 공공기관·등록 사이트만 표시함. 자격 조건은 공식 원문을 우선하고 없으면 검색·첨부 공고 기준임을 표시하며, 대안 공고는 API 원본이 있으면 그 값으로 채움. 가상 신청자 15명 테스트(공고 산정 기준): 첫 실행 7명 정답 → 오류를 고친 뒤 11명 정답, 4명 부분 정답.

주요 오류와 보완:
• 같은 정책 금액을 답할 때마다 다르게 말함(구직촉진수당은 공식 데이터 안에서도 월 50만 원과 60~100만 원으로 기록이 갈림) → 공식 출처를 우선하고, 최신 공식 원문과 금액이 다르면 자동으로 다시 작성하게 함
• 판정에 필요한 정보가 없을 때 자격을 추측함 → 서버가 확인된 조건으로만 판정하고, 빠진 정보는 한 가지씩 되묻게 함(가구원 수 → 가구 소득 → 판정 3턴)
• 세전 소득으로 판정하고 특례·주택 보유를 놓침 → 근로소득 30% 공제, 원가구·독립 특례 경로, 무주택·재산 조건을 서버가 계산
• 배포 사이트에서 답변이 끊김(Netlify 30초 제한) → Vercel(300초)로 이전하고 진행 과정을 실시간 표시
• 서류 원본에 담긴 개인정보가 AI 서버로 전송됨 → 텍스트 서류는 주민번호·전화번호·계좌번호를 가린 뒤 전송하고, 이미지·PDF 원본과 내 정보의 전송 사실을 화면에 알리고 체험용 가상 서류를 제공함

남은 한계: 답변에 30~170초가 걸림. 질문 1건당 Gemini 호출 4~10회, 비용 약 130~770원(Standard 요금·환율 1,400원 기준 추정). 자동 테스트는 카드 형식·비용 합산·인스타 링크 해석 점검 3종뿐임. 결과는 사전 점검이며 최종 판정은 접수 기관이 한다는 점을 모든 답변에 표기함.

확장 계획: 공고 응답 캐시와 도구 병렬 호출로 지연·비용을 줄이고, 판정 규칙 테스트를 늘리며, 이미지·PDF 서류도 전송 전에 가리도록 개선할 예정임.
