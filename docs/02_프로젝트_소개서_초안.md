## 1. 표지

- **반려제로** — 신청 전에, 떨어질 이유부터 찾아 주는 청년 지원금 사전 점검 에이전트
- 2026 대한민국 청년 CAREER FAIR AI 해커톤 / 주제: AI 에이전트로 푸는 청년의 일·생활 문제

## 2. 문제 정의: 받을 수 있는 돈인데 왜 포기할까

**핵심 메시지:** 청년은 지원사업을 찾은 뒤에도 자격 해당 여부와 증빙서류의 내용·발급 형식을 스스로 확인해야 한다. 접수 뒤에 오류를 알면 기한 안에 서류를 다시 준비해야 하므로, 신청 전에 무엇을 확인하고 보완할지 알려 주는 기능이 필요하다. (팀원 자료조사)

1. 공고문을 읽을수록 '받을 수 있다'는 확신은 줄고 할 일만 늘어난다.
2. 공고문은 본문·별표·주석에 탈락 조건("단, ~인 경우 제외")을 흩어 놓은 조건문 미로다.
3. 청년이 아는 '일상의 나'와 공고가 요구하는 '행정 데이터의 나'가 달라, 서류를 다 떼어 보기 전에는 자격조차 모른다.
4. 심사는 사후 판정이라, 반차를 내고 서류를 떼도 옵션 하나를 놓치면 0원이 된다.

**숫자로 본 문제 (넣을 그림: 포기 시점 막대그래프 한 장)**

| 근거 | 수치 | 출처 |
| :--- | :--- | :--- |
| 청년이 신청을 포기하는 시점 | **조건 확인 단계 60%**, 서류 준비 단계 20% | 인천 동구 청년정책 인식 설문(2025-12, 115명) |
| 검토·신청 때 가장 큰 부담 | "내가 대상자인지 판단하기 어렵다" 25.9%, "소득·재산 기준이 복잡하다" 17.4% (복수 응답) | 같은 설문 |
| 신청하지 못한 이유 | "대상자가 아니어서" 60.6%, "정책을 몰라서" 25.1% | K-공감 설문(2026-09, 310명) |
| 청년정책을 쓰지 않은 이유 | "신청조건이 해당되지 않아서" 54.9%, "찾는 법을 몰라서" 39.3% | 청년데이터연구소(2026-09, 281명) |
| 서류가 빠지면 | 온라인은 필수·추가 서류가 없으면 접수 불가, 방문 신청은 15일 안에 보완하지 않으면 직권 취소 | 국토교통부 청년월세 한시 특별지원 매뉴얼(2024-04) |

- **"대상이 아니라서"가 정말 대상이 아닐까:** 청년월세의 소득 기준은 세전 월급이 아니라 소득평가액(소득 − 근로·사업소득 30% 공제)이다(같은 매뉴얼). 월 180만 원을 버는 청년은 세전으로는 1인 기준 중위소득 70%라 "안 된다"고 보기 쉽지만, 공제하면 49%로 기준(60%) 안에 든다. 스스로 판단해 포기하는 60% 중 일부는 실제로 받을 수 있는 사람이다.
- **포기 지점이 곧 반려제로의 기능:** 조건 확인(60%)은 ② 자격 사전 판정, 서류 준비(20%)는 ③ 제출 서류 검수가 맡는다.
- 공공 데이터만으로도 마감을 알기 어렵다: 온통청년 정책 600건 중 기간이 지정된 290건의 48건이 신청기간 300일 이상, 41건이 사업기간과 같음 (2026-11-18 직접 조회).
- 출처 링크
  - 인천 동구 설문: https://youth.incheon.go.kr/donggu/vote/voteAnswResult.do?vote_seq=158 (포기 시점, 대상 판단의 어려움)
  - K-공감 873호(2026-09-19): https://gonggam.korea.kr/newsContentView.es?mid=a12505000000&section_id=NCCD_SPECIAL&content=NC002&news_id=18c95db8-90bf-47ad-98ac-9b618a4f6ba0 (신청하지 못한 이유)
  - 청년데이터연구소 조사 보도(아시아경제, 2026-09-18): https://view.asiae.co.kr/article/2026091808415254712
  - 국토교통부 매뉴얼: https://www.yeongdo.go.kr/_res/portal/data/pdf/p04564_data01.pdf (12쪽 신청 절차, 53쪽 소득·재산 산정 기준)
- 주의: 설문 세 개는 표본이 작고(115~310명) 질문이 서로 다르다. 소개서에는 "청년 설문에서 반복해서 나타난 경향"으로 쓰고, 하나의 통계처럼 합치지 않는다.

## 3. 대상 사용자와 대표 시나리오

- 대상: 정부·지자체 지원 정책 신청을 준비하는 청년, 행정 용어에 익숙하지 않은 사람
- 시나리오 A (주거): 청년월세 지원 — 원가구·독립가구 조건, 등본·임대차계약서·확정일자 교차 검증
- 시나리오 B (일·구직): 국민취업지원제도 구직촉진수당 — 가구 소득 판독, 취업활동계획서 초안
- 시나리오 C (지역): 대구 청년 주거지원 — 지역 공고와 중개보수 영수증까지 점검 (가상 세트 C)
- 시나리오 D (SNS): 인스타그램에서 본 정책 릴스 — 링크를 넣으면 캡션·대본을 공식 공고와 대조해 마감 여부까지 확인
- 시연영상은 시나리오 C(서류 검수)와 D(릴스)를 쓴다 ([03_시연영상_대본.md](03_시연영상_대본.md)). 【확인: 발표에서도 같은 두 장면을 쓸지】

## 4. 반려제로가 하는 일

**핵심 메시지:** 정책 탐색 → 자격 사전 확인 → 제출 서류 검수 → 오류 보완 → 신청 준비를 하나의 에이전트 흐름으로 잇는다. 기능은 7개로 묶어, 없으면 안 되는 것(Must 3)·있으면 좋은 것(Should 2)·기대하지 못한 즐거움을 주는 것(매력 2)으로 나눴다.

| 구분 | 기능 | 하는 일 | 왜 이 구분인가 |
| :--- | :--- | :--- | :--- |
| **Must** | ① 맞춤 공고 찾기 | 온통청년·보조금24·복지로에서 내 지역·상황·관심 분야와 관련 있는 공고만, 마감이 확인된 공고부터 보여 준다 | 점검할 공고가 있어야 시작할 수 있다 |
| **Must** | ② 자격 사전 판정 | 공고 조건과 내 정보를 서버가 대조해 충족·미충족·추가 확인을 나눈다. 원가구·독립 특례 같은 대체 경로와 근로소득 공제까지 계산하고, 아깝게 놓친 조건도 보여 준다 | "받을 수 있나?"에 답하지 못하면 서비스가 성립하지 않는다 |
| **Must** | ③ 제출 서류 검수 | 올린 서류를 판독해 누락, 발급일, 성명·주소 일치, 직인을 점검하고 서류 간 교차 검증 후 보완 방법을 알려 준다 | '반려 0'이라는 이름 그대로의 핵심 가치 |
| **Should** | ④ 공식 원문 대조 | 답변의 금액·조건을 가장 최근 수정된 공식 원문과 비교하고 기준 시점과 출처를 붙인다 | 정확할수록 만족이 커지는 신뢰 기능 |
| **Should** | ⑤ 제출 준비 패키지 | 제출 직전 체크리스트, 소명서·사유서 초안, 엑셀·CSV·워드·텍스트·캘린더 파일을 만든다 | 있으면 편하고, 없어도 핵심 가치는 남는다 |
| **매력** | ⑥ 안 될 때 대안 추천 | 자격이 안 되면 이유를 밝히고, 사용자가 원래 이루려던 목적에 맞는 다른 지원을 실제 공고에서 찾는다 | "안 됩니다"에서 끝날 거라 예상한 사용자에게 놀라움을 준다 |
| **매력** | ⑦ 공고문·인스타 게시물 → 정리·검증 | 공고문을 올리면 본문·별표·단서의 숨은 예외·특례 조건을 "부모님과 따로 산 지 1년이 넘었나요?" 같은 질문 3~4개로 바꾼다. 인스타그램 릴스·카드뉴스 링크를 넣으면 캡션과 대본(텍스트)을 가져와 공식 공고와 대조하고, 게시물과 다른 점과 마감 여부를 알려 준다 | 청년이 정책을 처음 접하는 SNS 정보까지 신청 전에 검증하는, 기존 서비스에 없는 장면 |

- **7개에 넣지 않은 것:** 답변 자동 점검 9가지, 개인정보 마스킹, 정보가 없을 때 되묻기는 기능이 아니라 신뢰 장치라서 7장에서 설명한다. 알림, 대화 기록, 사이트 추가, 에이전트 화면 연출은 서비스에 있지만 소개서에서는 강조하지 않는다.
- 넣을 화면: Must 3개가 이어지는 한 장면(공고 선택 → 자격 판정 카드 → 서류 검수 리포트), 매력 기능은 6장 시연 결과와 함께

## 5. 왜 AI 에이전트인가, 어떻게 쓰나

**핵심 메시지:** 공고마다 조건 구조가 달라 고정 규칙으로는 못 푼다. AI는 공고를 읽고 필요한 도구를 고르고, 판정은 서버 코드가 한다.

- **왜 AI인가:** 공고문의 별표·단서 조항을 해석하고, 사진으로 찍은 서류를 읽고, 사용자의 일상 언어를 행정 조건으로 바꾸는 일은 규칙 코드로 만들 수 없다.
- **어떻게 쓰나:** 질문과 첨부 서류를 바탕으로 도구 11개 중 필요한 것을 스스로 골라, 공고 조회부터 조건 대조, 서류 검수, 답변 검증까지 이어서 실행한다 (최대 9회).
  - 도구: 공고 목록 조회·검색, 공식 원문 확인, 자격 확인, 서류 검수, 대안 탐색, 실행 계획, 되묻기, 체크리스트, 초안, 파일 생성
- **되묻기와 추론 수준 전환:** 전입일처럼 판단에 필요한 정보가 없으면 사용자에게 묻거나 추가 확인 항목으로 표시한다. 일반 검색·요약은 기본 추론, 예외 조건 해석 같은 복잡한 요청은 깊은 추론을 쓴다.
- **자동 재확인:** 답변의 지원 금액을 최근 수정된 공식 원문과 대조하고 계산값과 판정도 점검한다. 고칠 항목이 있으면 최대 한 번 다시 쓰고 재검증한다.
- 넣을 화면: 실행 계획 패널, 도구 실행 기록

## 6. AI가 실제로 기여하는 곳 (시연 결과)

**핵심 메시지:** AI가 서류를 요약하는 데서 그치지 않고, 여러 서류 사이의 정보를 비교해 신청 과정의 위험 요소를 찾아낸다.

- **시연 결과 (가상 세트 C, 서류 3건: 주민등록등본·임대차계약서·중개보수영수증):**
  - 주소 호수 불일치 (등본 301호 / 계약서 302호)
  - 성명 불일치 (김청년 / 영수증 지급인 김철수)
  - 전입일 미표시
- **시연 결과 (실제 인스타그램 릴스, 2026-11-20 공개 사이트):** 2026 청년정책 공모전 안내 릴스 링크만 넣자, 캡션(게시일 10-23, "마감 일주일 전!")을 가져와 공식 안내와 대조하고 "10.30 이미 마감돼 신청 불가"로 답했다. 게시물 내용은 공식 안내와 같다고 밝히고, 대신 참여할 수 있는 청년정책 참여 사업 3개를 제시했다. 영상은 받지 않고 캡션·대본 글자만 썼다 (응답 약 1분).
- **공고 조건 → 일상 질문:** 공고문을 올리면 숨은 예외·특례 조건을 "부모님과 따로 산 지 1년이 넘었나요?" 같은 질문으로 바꾼다.
- **오류에서 끝나지 않는 행동 안내:** 확인이 필요한 항목과 보완 사항, 소명서·사유서 초안, 제출 전 체크리스트, 자격이 안 될 때 대안 정책까지 이어서 준다.
- **사용자 편익:** 시간 절감(검색·자격 비교·서류 검토를 한곳에서), 신청 오류 예방(제출 전 누락·불일치 발견), 접근성 향상(쉬운 설명과 체크리스트), 신청 기회 확대(미충족 시 다른 지원 탐색)
- 현재 역할은 신청 전 사전 점검과 준비 지원까지이며, 실제 제출과 최종 심사는 담당 기관의 영역이다.
- 넣을 화면: 서류 검수 리포트(통과·반려 위험 배지와 보완 방법)

## 7. 틀릴 수 있는 AI를 어떻게 막나

**핵심 메시지:** AI는 해석과 도구 선택만 맡고, 숫자와 판정은 서버가 하고, 답변은 내보내기 전에 한 번 더 점검한다.

**오류 사례 (팀원 자료조사):** 사용자가 2026년 청년월세 지원 한도를 물었는데 AI가 2022년 공고를 참조해 "월 최대 20만 원씩 12개월, 총 최대 240만 원"이라고 답하는 경우. 2026년 공식 안내의 지원 기간은 최대 24개월이다. → 2026년 공식 원문과 월 지원액·지원 기간·총한도를 대조하고, 다르면 "실제 납부한 월세 범위에서 월 최대 20만 원씩 최장 24개월, 총 최대 480만 원"으로 고쳐 다시 검증한다. (복지로 「청년월세 지원사업」 기준연도 2026 페이지에서 확인, 11-21: 월 최대 20만 원, 최장 24개월, 생애 1회, 2026년 6만 명 선정)

## 8. 기존 서비스와 무엇이 다른가

**핵심 메시지:** 정책을 찾는 데서 끝나지 않고, 신청 과정의 반려 위험을 미리 찾아 보완까지 돕는 사전 예방형 에이전트다.

**이미 있는 서비스와 비교 (11-21 확인한 범위)**

| 서비스 | 하는 일 | 반려제로가 더하는 것 |

**핵심 아이디어**

1. **'반려 가능 원인'에 집중한 역방향 접근:** '어떤 지원을 받을 수 있나'가 아니라 '어떤 이유로 문제가 생길 수 있나'에서 출발한다. 공고 본문뿐 아니라 별표·주석의 예외 조건과 서류의 실제 기재 내용을 함께 확인한다.
2. **AI 판단과 규칙 기반 검증의 결합:** AI는 공고 해석과 서류 판독, 수치 비교와 판정은 서버 코드. 금액과 답변을 공식 원문·도구 결과와 대조한다.
3. **행동 중심:** 오류를 표시하는 데서 끝내지 않고 다음에 할 일(보완, 초안, 체크리스트, 대안)을 안내한다.

## 10. 비용·운영과 확장 계획

**핵심 메시지:** 어떤 정책에도 같은 흐름을 쓰는 범용 구조이고, 요청마다 비용을 기록하고 있어 확대할 때 품질과 비용을 숫자로 관리할 수 있다.

- **비용:** 질문 1건당 Gemini 호출 4~10회, 약 130~770원(Standard 요금·환율 1,400원 기준 추정). 인스타그램 링크는 캡션·대본 조회 2회에 약 $0.004(약 5원)이 더 들고, 같은 링크는 하루 동안 저장된 응답을 써서 추가 비용이 없다. 난이도 판단은 가장 낮은 추론으로 빠르게 하고, 일반 안내는 medium, 어려운 해석만 high로 처리한다.
- **운영:** 사용자 정보를 서버에 저장하지 않아 DB·보안 운영 부담이 작다. 공공 API 키와 Gemini 사용량 한도만 관리하면 된다.
- **규모별 비용 (위 추정 기준):** 질문 1,000건에 약 13만~77만 원. 대부분의 비용은 도구를 여러 번 부르는 정책 질문과 서류 검수에서 나오므로, 아래 결과 캐시와 병렬 호출이 비용을 줄이는 첫 단계다.
- **운영 위험과 대응:** 개발 기간에 AI 사용 한도가 차서 서비스가 멈춘 적이 있다 → 요청마다 비용을 기록하고, 심사·운영 기간에는 한도를 예상 사용량보다 넉넉히 잡고 사용량 알림을 켠다. 인스타 조회 크레딧도 같은 방식으로 관리한다.
- **확대할 때 품질 관리:** 정책을 늘릴 때마다 가상 신청자 테스트를 추가하고, 공식 기준으로 정한 정답과 비교한 정확도를 숫자로 관리한다 (현재 청년월세 15명 중 11명 정답, 오판 0명).
- **범용 구조:** 정책마다 다른 내용을 지원 대상·신청 기한·필수 서류·예외 조건·공식 출처로 정리하면, 월세에서 취업·교육·지역 복지로 넓혀도 공고 탐색 → 자격 대조 → 서류 검수 → 보완 안내 흐름을 그대로 쓴다. 새 정책은 세부 조건과 서류 양식을 검증한 뒤 적용한다. 현재 API는 정책 정보 조회까지이며, 실제 접수와 결과 전달은 운영 기관과 별도 연계가 필요하다.

| 발전안 | 적용 방식 (팀원 자료조사) |
| :--- | :--- |
| 결과 캐시 | 공개 공고, 추출한 자격 조건, 공통 서류 목록을 출처·공고 ID·수정일 기준으로 저장해 반복 조회와 AI 분석을 줄인다. 공고가 바뀌거나 마감되면 갱신하고, 개인별 결과와 원본 증빙은 공용 캐시에 넣지 않는다. |
| 공식 제출·결과 연계 | 연계가 승인된 사업부터 본인인증 → 제출 항목 확인 → 기관 접수 → 접수번호 확인 → 보완 요청·심사 결과 수신을 잇는다. 발급 가능한 행정 증빙은 공공 마이데이터 활용을 검토한다. |
| 기관 제휴 | 시연에 쓴 대구 청년 주거지원처럼 제출 요건을 확인할 수 있는 사업 1개를 시범 대상으로 제안한다. 지자체 담당 부서와 청년센터가 실제 보완 사유로 검수 항목을 검증하고, 접수·통보 기능은 소관 기관과 디지털서비스개방지원센터와 협의한다. |

- **최종 목표:** 정부 사이트를 따로 방문하지 않아도 한 화면에서 지원사업을 찾고, 서류를 내고, 심사 결과까지 받는 것. 민간 앱에서 여권 재발급을 신청하거나 국민비서로 교육비 지원 심사 결과를 받는 사례처럼, 민간 채널을 통한 신청과 결과 통보는 이미 쓰이고 있다.
